# Правило возврата WayYaam

**А → Б → В → Назад → Б → Назад → А.** Возвращаем пользователя к его предыдущему экрану, а не к заранее выбранной родительской странице. Правило распространяется на клиента, каталоги, кабинет курьера, кабинеты заведений и суперадминистратора. Ресторан и магазин используют общие компоненты; история каждого заведения изолирована.

## Общий механизм

`ExactBackProvider` внутри HashRouter хранит журнал настоящих записей history. `useExactBack` обслуживает маршрутные стрелки, `useBackAction` — переиспользуемые кнопки внутренних экранов. Оба сначала используют известную запись своего контекста; прямой вход использует безопасный fallback с replace. Старые неотслеженные ссылки могут использовать явно сохранённую внутреннюю точку входа, без предположения о предыдущем слоте browser history.

`useHistoryViewState` превращает внутренний экран, вкладку или панель в реальный шаг history даже при неизменном адресе. Несколько изменений в одном действии объединяются. `useViewNavigate` переносит их в тот же переход при одновременном изменении адреса (например, сворачивание корзины). `useEntrySnapshotState` хранит поиск, фильтры и выбранную секцию в снимке записи без дополнительных шагов истории. Наблюдатели прокрутки не должны вызывать navigation setters.

PUSH открывает новый экран сверху. POP восстанавливает URL/query/router state, локальные navigation state и прокрутку окна/помеченных контейнеров. При медленной загрузке содержимого восстановление ожидает высоту до 10 секунд; пользовательский жест прекращает ожидание. Контейнеры помечаются стабильным `data-navigation-scroll`. REPLACE для синхронизации сохраняет родителя; безопасный fallback не создаёт петлю «назад».

Журнал и снимки ограничены 100 записями текущей вкладки. SessionStorage позволяет восстановиться после перезагрузки, память обеспечивает работу при заблокированном хранилище. Снимки обрезаются вместе с журналом и сериализуются на переходах/скрытии страницы, а не на каждом событии прокрутки. Browser/Android/PWA Back и видимая стрелка используют одну history. Начальный неизвестный browser history не считается внутренней историей приложения.

## Роли и данные

Контексты: client, driver, platform, restaurant:<slug>. Вход, смена роли и смена рабочего заведения в кабинете начинают отдельную цепочку. Переход клиента между публичными каталогами сохраняет его обычную цепочку. Проверенные идентификаторы из существующих role gates связывают снимки с аккаунтом там, где gate предоставляет личность; смена пользователя очищает снимки до отображения. Старые ответы не должны восстанавливать выбранный заказ другого аккаунта. Заказ заведения хранится как ID и берётся из актуального разрешённого набора данных. Снимок экрана не является авторизацией: редактор каталога остаётся под `isAdmin`.

Возврат восстанавливает интерфейс, а не откатывает оплату, отправку заказа, QR или статус доставки. Существующие backend permissions, подтверждения выхода и переходы после завершённых операций сохранены. Пароли и токены в navigation snapshots не добавляются. Неподтверждённые произвольные черновики форм не объявляются восстановленными после перезагрузки; сохранённые данные берутся из существующих моделей.

## Обход кнопок и экранов

| Поверхность | Подключённый механизм и проверка |
| --- | --- |
| Главная, профиль, адреса, оплата, избранное, уведомления, город, списки заведений, материалы, заказы | Общий клиентский PageHeader; реальные входы и вложенная история, вкладка завершённых заказов |
| Каталог, поиск, категории, товар, отзывы ресторана/магазина | Публичный TopBar и стрелка каталога; экран товара в history, фильтры и наблюдаемая категория в snapshot; реальные Мангал/Финик |
| Корзина и checkout | Стрелка, Escape/фон и браузерный Back возвращают источник. Полоска сворачивает в каталог отдельным действием; атомарно сохраняются UI и query. Товары не удаляются |
| Статус заказа, чат заведения, контактные вкладки курьера | Маршрутный Back и локальные вкладки; статус остаётся актуальной моделью, а не откатываемым снимком |
| Старый кабинет заведения `/:slug/dashboard/orders/dishes/finance/settings/scanner/pos` | Маршруты, локальная карточка заказа по ID, вкладки доставки, финансовые фильтры, общие settings headers |
| Кабинет `/admin/catalogs/:slug` | Разделы и вложенные настройки в history; поиск блюд/заказов, фильтр категории, выбранный заказ — snapshots |
| Профиль, дизайн, тема, качество фото, категории, зал/кабинки, платежи, импорт, удаление | SettingsHeader + ExistingRestaurantSettingsPage; локальные экраны/режимы редакторов записываются отдельно, вложенный возврат не прыгает в корень |
| Доставка: курьеры/платформа и параметры | Две стрелки DeliverySettingsCard восстанавливают предыдущий уровень; данные настроек/доступы сохранены |
| Редактор блюда/дизайна | DesignEditor/DishEditorPage возвращают источник; сохранённый редактор доступен только авторизованному администратору |
| POS | Выбор категории и карточка блюда — локальные переходы; закрытие карточки возвращает источник, поиск не создаёт шагов истории |
| Курьер: заказы, предложение заказа, активная доставка, QR, баланс, профиль, настройки, поддержка | Общий DriverHeader и отдельная стрелка предложения; вкладки заказов и контактов/чат входят в history. Внешний Яндекс Навигатор сохранён |
| Суперадминистратор: основные разделы | Переходы перенесены с raw pushState на общий router; Back/Forward видит реальные ключи и URL |
| Подписки, комиссии, лимиты, тарифы, маршруты, POS/склад | PlatformInnerHeader и локальные view state; выбранное заведение/поиск в snapshot |
| Баннеры, страницы, редакторы, предпросмотр, поддержка | PlatformInnerHeader; сначала возврат из редактора к списку, затем к настройкам; закрытие после сохранения не создаёт пустой шаг |
| Акции/конкурсы | Переход в настройки через router; открытая карточка в history, выбранная акция/фильтр сохраняются |
| Регистрация партнёра и демонстрационные экраны | Шаги/экраны в history; реальная предыдущая роль/экран, не фиксированное дерево |
| Отдельный и встроенный сканер | Известная история или безопасный fallback внутри текущей роли; нет blind Back |

Пагинация таблицы, слайды инструкции установки и карусели — команды «предыдущий элемент» внутри содержимого. Они не являются переходом на прошлую страницу и не добавляют невидимых шагов после закрытия инструкции. Кнопки с явным назначением («Вернуться в профиль», «На главную», «Открыть заведение») сохраняют указанное назначение. Выход требует прежнего подтверждения и не подменяется Back.

## Поведенческие доказательства

`all-back-navigation.test.tsx`: все контексты маршрутов, локальные вложенные экраны, пакетные изменения, фильтр без лишних history entries, независимая прокрутка, медленная загрузка, недоступный storage, прямой вход, атомарное сворачивание корзины и границы заведений.

`role-back-controls.test.tsx`: настоящие настройки Мангал/Финик (тема → дизайн → настройки; параметры → доставка → настройки), настоящий header курьера с необычной точкой входа, редактор баннеров, регистрация, смена проверенного аккаунта.

Дополнительно сохраняются checkout/cart/order/PWA/POS/payment/QR/driver тесты. `navigation-scope.test.ts` проверяет роли, tenant boundaries и внутренние маршруты; mutation report относится к этому модулю, а не ко всему приложению.

Отдельные проверки собранного и опубликованного сайта находятся в отчёте выпуска: public catalog/product Back, клиентские заказы и свайп корзины на 319×620 и 390×620. Авторизованные рабочие места проверяются браузерными fixtures с существующими компонентами и моделями; это не доказательство входа реальными рабочими аккаунтами на production. Физический iPhone отдельно не заявляется.
